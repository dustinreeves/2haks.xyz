# Boss Builder runbook

**URL:** https://bossbuilder.2haks.xyz
**Folder:** `/opt/apps/bossbuilder` (a Git repo on the server)
**What it is:** a 2D platformer where you build a level and play the boss, while a horde of AI heroes tries to reach the flag.

## How it fits together

```
Browser ─► Caddy (host) ─┬─ /api/* ─► bossbuilder-api  127.0.0.1:8103 → :8000  FastAPI + SQLite (volume "levels")
                         └─ /*     ─► bossbuilder-web  127.0.0.1:8102 → :8080  nginx, static game files
```

- The whole game runs in the browser: physics, hero AI, editor and shop live in `web/public/js/`. Player progress (coins, unlocks, upgrades, current level) is saved in the browser's localStorage.
- The API only does level sharing: it stores a level and returns a 6-character code. There's no free text: level names are generated by the server.
- Both containers are also on the shared external `web-proxy` network.

## Ports

| Service | Host (127.0.0.1 only) | Container |
|---|---|---|
| web | 8102 | 8080 |
| api | 8103 | 8000 |

Registered in `/opt/apps/PORTS.md`.

## Environment variables (api)

| Name | Default | Meaning |
|---|---|---|
| `LEVELS_DB` | `/data/levels.db` | SQLite file (in the `bossbuilder_levels` volume) |
| `MAX_LEVELS` | `5000` | Stop accepting new levels after this many (returns 507) |
| `SHARES_PER_HOUR` | `20` | Shares allowed per client IP per hour (returns 429) |

Set in `docker-compose.yml`. No secrets. The web container has no settings.

## Build and start / stop

```bash
cd /opt/apps/bossbuilder
docker compose up -d --build     # build and start, or deploy a change
docker compose ps                # status + health
docker compose restart api       # restart one service
docker compose down              # stop (the levels volume is kept)
```

Never run `docker compose down -v`: it deletes all shared levels.

## Health checks

```bash
curl -fsS https://bossbuilder.2haks.xyz/api/health   # {"status":"ok","levels":N}
curl -fsS http://127.0.0.1:8103/api/health           # API without Caddy
curl -fsS http://127.0.0.1:8102/healthz              # web without Caddy
```

## Logs

```bash
docker compose logs -f api       # shares, rate limits, errors
docker compose logs -f web       # nginx access log
sudo journalctl -u caddy -f      # HTTPS / proxy
```

Docker keeps at most 3 × 10 MB of logs per container.

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/health` | `{"status","levels"}` |
| GET | `/api/levels?limit=12` | Recently shared levels (limit 1–50) |
| GET | `/api/levels/{code}` | One level with its data; 404 if unknown |
| POST | `/api/levels` | Body `{"level": {...}}`, max 16 KB. 201 when new, 200 if the same level was already shared (same code). 422 invalid, 429 rate limited, 507 full |

Interactive docs: https://bossbuilder.2haks.xyz/api/docs

## CLI

`/usr/local/bin/bossbuilder` is a symlink to `cli/bossbuilder` (Python 3, no packages needed).

```bash
bossbuilder health
bossbuilder list
bossbuilder show K7M2QX          # draws the level as text art
bossbuilder get K7M2QX -o level.json
bossbuilder validate level.json
```

## Tests

```bash
cd /opt/apps/bossbuilder/api && python3 -m unittest discover -s tests
```

Game logic tests run in a browser. Serve `web/` and open `/tests/`:

```bash
cd /opt/apps/bossbuilder/web && python3 -m http.server 5198 --bind 127.0.0.1
# then, from your computer: ssh -L 5198:127.0.0.1:5198 2haks  and open http://localhost:5198/tests/
```

## Backups

Shared levels live in the Docker volume `bossbuilder_levels`. To copy the database out:

```bash
docker compose exec api python -c "import sqlite3; s=sqlite3.connect('/data/levels.db'); d=sqlite3.connect('/tmp/b.db'); s.backup(d)"
docker compose cp api:/tmp/b.db ./levels-backup-$(date +%F).db
```
